# 架构与实现

## 分层

| 层次 | 文件 | 职责 |
| --- | --- | --- |
| 展示 | `static/` | 文件预览、模型配置、事件日志、引用弹窗、结果阅读与下载 |
| 本地服务 | `app.py` | 同源检查、任务排队、配置快照、SQLite 历史、导出路由 |
| 工作流 | `engine.py` | LangGraph 状态和节点、模型调用、Schema 校验、审核恢复 |
| 资料处理 | `documents.py`、`pptx_render.py` | 解析、范围、证据切分、PowerPoint 整页渲染 |
| 支撑 | `model_connection.py`、`credentials.py`、`runtime_settings.py` | 服务配置、共享限流、DPAPI 与偏好保存 |
| 导出 | `exports.py` | DOCX、Markdown 和 Anki 内容生成 |

HTTP 服务基于标准库 `ThreadingHTTPServer`，监听回环地址，面向个人本机。SQLite 保存任务及事件，原文件与导出保存在任务子目录中。

## 共享状态与图执行

`StudyState` 用 `TypedDict` 声明字段。提取节点返回 `{"notes": [...]}`，`notes` 用 `Annotated[list[dict], operator.add]` 归并并行分支，其他结果由对应节点写入。状态由工作流管理，并不是几个独立聊天自动同步记忆。

`prepare` 后用动态 `Send` 为每个来源生成一个提取任务；完成后进入去重整理，再让 `questions` 与 `cards` 并行。`add_edge(["questions", "cards"], "review")` 形成等待两路完成的汇聚点，避免审核只拿到一半结果。

节点是 Python 函数，调用同一个兼容模型客户端来扮演不同角色；可为文字和视觉分别配置服务。项目没有使用 OpenAI Agents SDK，也没有 Codex 内建子 Agent，自主调度工具并非当前能力。

## 证据交接

1. 保留原页号/片段位置，为来源建立稳定 `source_id`。
2. 将文字按带重叠的 180 字符窗口切分，每个窗口分配 `evidence_id`。
3. 模型仅从本节点收到的证据编号中选择，不自行生成引用文本。
4. 程序回填 `source_id` 与原文摘录，并逐字匹配；跨来源、伪造或未交接的编号会被拒绝。
5. 后续文字模型根据条目及引用判断语义支持关系，剔除证据不足项。

出题和制卡每批最多接收 8 个知识点及其使用到的证据。交接内容有范围，历史不会无限叠加到所有后续请求。

视觉来源先经过模型识别，再形成证据窗口。这些摘录是识别描述，不是原图中的逐字引文。来源会保留图片、页号、识别模型与不确定性；后续文字审核不构成独立图像复核。

## 失败恢复

| 类型 | 行为 |
| --- | --- |
| JSON/Schema/引用错误 | 给出具体字段与约束，带上上次输出，最多修正一次 |
| 明确 `finish_reason=length` | 审核批次二分缩小，最低单条；其他节点或单条从干净上下文重生成，不追加残缺 JSON |
| 服务拦截、资源不足、服务中断、未知结束码 | 分别报告；不当作长度问题或格式问题重试 |
| 网络/HTTP 错误 | 结束并保留可读错误；不自动重试 |
| 达到请求预算 | 停止，不返回未经完整审核的成功结果 |

审核初始每批最多 5 条。每次拆分或修正都计入请求总数；最坏请求估计包含拆分树及格式修正，实际仍受用户预算限制。

成功 JSON 的 `diagnostics.responses` 记录节点、批次、结束原因、额度、用量和正文/思考字符数，失败日志也包含可得的诊断。不会保存原始思考文本或无效答案；普通 Word/Markdown 只显示合计用量。

## 并发与状态持久化

`RequestLimiter` 用 `Condition` 管理活动请求数和准入容量，改变限额时不替换正在使用的信号量，也不中断已发出的请求。LangGraph 的最大并发与共享模型请求限额一起生效，所有模型相关接口共用服务实例的 limiter。

任务开始时使用其并发快照，结束时恢复最新偏好。用户修改配置不改变正在执行的任务的模型连接或并发设置。DPAPI 凭据与非敏感运行偏好分开保存。

当前没有工作流 checkpoint；中途停止不能自动续跑。没有向量数据库、持久化对话记忆或知识库检索。此处的“原文证据”来自用户本次选中的资料。

## 权衡

分工能让节点职责和上下文更明确，也能并行执行相互独立的出题/制卡；代价是额外请求、审核耗时与调用失败面。短任务可能直接一次模型调用更快。本项目没有用未测量的数据宣称编排必然更快、更便宜或完全正确。
